# 02 Swift 代码约定

[返回主 PRD](../PRD.md) · [架构](01-project-foundation.md) · [验收](10-delivery-and-acceptance.md)

本文件约束后续原生实现，不要求本次生成 Swift 文件。旧 Flutter 的语言、目录及工具规范不直接用于原生项目。

## 1. 命名与组织

- 类型、协议使用 UpperCamelCase，方法与属性使用 lowerCamelCase；名称表达业务含义，避免 `data1`、`tempModel` 等泛化命名。
- 文件按主要类型或职责命名；业务模块边界与 01 保持一致。视图结构过长时拆成有含义的子视图，不用一个 View 包含所有页面。
- 限制访问级别，默认不暴露可变状态；不为所有实体引入继承或无实际用途的协议。
- 界面文案集中于可本地化资源；API 字段和枚举原值必须与后端一致。

## 2. 类型与数据

- DTO 使用明确 Codable 类型，金额字段为 String；业务层转换为精确金额类型，不能使用 `[String: Any]` 贯穿全项目。
- 业务 ID 使用可覆盖后端安全整数范围的整数类型；提交 ID 来自真实服务，不生成本地业务 ID。
- `occurredDate`、月份、年份建模为自然日期 / 周期，不套用统一 ISO 时间点解码。
- 可空字段明确建模；写入 `title` / `remark` 清空时须显式 encode null，不能因 `encodeIfPresent` 自动省略而违背完整 PATCH 契约。
- 成功无 data 与需要 data 的查询使用不同解码路径。坏响应不得用空模型兜底后显示成功。
- 对非法输入和未知枚举给出可诊断错误，不在正式流程用 `try!`、强制解包或 `fatalError` 掩盖可恢复问题。

## 3. 并发与生命周期

- UI 状态在 MainActor 上修改；网络等待不阻塞主线程。长期凭证、刷新和身份切换通过 actor / 串行操作协调。
- 明确 Task 的持有者、取消时机、结果接收条件；View 重算不重复启动写入或创建会话。
- 对跨 actor 数据遵守所选 Swift 模式的 Sendable 检查，不用普遍 `@unchecked Sendable` 规避问题。
- 刷新任务共享、请求最多一次认证重放；JSON body 可复用。传输重试与认证重放不使用同一个无限循环。
- 相同提交动作有加载锁，关闭、取消、保存和子面板返回分别处理；不可通过手势绕过未保存确认。

## 4. 注释与文档

- 手写类型、业务模型字段、方法、初始化器与对外接口提供中文说明；方法使用 `///` 说明用途，必要时包含参数、返回、异常与副作用。
- 状态属性说明作用域、持有者和含义；金额注明单位，日期注明自然日期，Cookie 注明存储边界。
- 必须解释以下关键节点：刷新共享与轮换、身份代次、Keychain 原子替换、金额解析、日期桥接、查询白名单、标签草稿事务、归档口径、写成功与刷新失败的区别。
- 注释与修改同步，描述“为什么 / 规则是什么”，避免只把语句翻译成中文。局部循环变量等不强制重复无信息注释。
- 生成文件不手工补注释；检查结果需要人工复核语义，不以注释数量替代可维护性验收。

## 5. 原生资源与界面

- 视觉数值集中在 DesignSystem，使用 08 的语义 Token；禁止页面各自选一套黄色或收支配色。
- 分类图标映射集中维护；未知 key 有占位。运行时不依赖 Web Symbol、CSS 或远程图标脚本。
- Preview 可使用明确标记的 fixture，正式依赖装配不能落回假接口；测试账号和凭证不提交到仓库。
- 支持 Dynamic Type、VoiceOver、Reduce Motion；不通过全局锁字号或隐藏错误来通过布局检查。

## 6. 检查要求

后续工程至少完成编译、关键契约 / 会话测试、关键页面 UI 验证。格式 / lint 工具是否引入由工程初始化记录确定，不将未安装工具写成已经通过的检查。具体测试范围与设备场景见 [10](10-delivery-and-acceptance.md)。
