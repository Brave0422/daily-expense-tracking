# 原生 iOS 产品需求文档

版本：v1.0 · 编写日期：2026-10-15 · 状态：PRD 已建立，原生工程待生成。

## 1. 产品目标

为 Daily Expense Tracking 建设原生 iPhone 客户端，替代后续移动端开发中的 Flutter 方案。用户可以完成账户认证、快速记账、历史查询、分类与标签管理、月 / 年收支分析，与现有 Web 共用 NestJS 服务和账户数据。

视觉延续 Web 的亮黄色强调、浅灰背景、白色圆角卡片、彩色分类图标及“支出绿、收入红”。页面结构、表单和图表交互按 iOS 使用习惯重新设计。目标是品牌和业务一致、手机操作顺手，不要求逐像素复制桌面布局。

本文件是入口，各模块需求分别保存在 `docs/`。本次交付仅包含文档和用户提供的设计参考图，不包含 Xcode 工程、Swift 源码或依赖安装。

## 2. 本轮产品与技术基线

| 项目 | 首版要求 |
| --- | --- |
| 开发目录 | 仓库根目录 `ios/`；后续原生工程放在此目录，与 `app/ios/` 区分 |
| 目标平台 | 原生 iOS；以 iPhone 竖屏为主要体验，兼顾横屏与大字体；Android 后续另行规划 |
| 最低系统 | 本 PRD 采用 iOS 17.0，便于统一使用 Observation 和原生饼图能力；这是本轮方案基线 |
| 实现方式 | Swift、SwiftUI、Observation、Swift Concurrency、URLSession、Keychain、Swift Charts |
| 语言与币种 | 默认简体中文，人民币；金额与日期遵守现有服务端契约 |
| 数据来源 | 联网使用，服务端为准；业务结果只做当前会话内存缓存 |
| 认证 | 兼容现有 Cookie 双 Token：内存 Access Token，Keychain 持久化 Refresh Cookie |
| 视觉基线 | 优先验收与 Web 接近的浅色主题；提供语义化深色适配，详见视觉规范 |
| 导航 | 流水、统计、管理三个底部入口；管理包含配置与账户安全 |
| 项目现状 | Web、后端、Flutter 初版已存在；本 PRD 是新的原生实现依据，旧 Flutter 代码保留参考 |

后续创建工程时记录实际 Xcode、Swift 编译器与 SDK 版本，不把最低部署系统误写成必须使用的 SDK 版本。本次不推定 Bundle ID、开发团队、签名或正式 API 域名已经确定。

## 3. 首版范围

| 模块 | 必须实现的能力 |
| --- | --- |
| 账户 | 登录、注册、邮件验证码、忘记密码、修改密码、启动恢复、退出登录 |
| 流水 | 日明细、年内月汇总、受接口支持的筛选、新增、完整编辑、归档删除 |
| 分类 | 收入一级、支出两级、名称和图标维护、受约束的归档删除 |
| 标签 | 管理页增改删与服务端搜索；流水中的选择、新名称草稿、改名草稿和同名复用 |
| 统计 | 月 / 年分类排行、分类占比、收支柱状趋势、上一完整周期比较 |
| 通用 | 导航与表单返回保护、联网状态、错误反馈、精确金额、自然日期、图标适配与无障碍 |

首版范围不包含 Android 新客户端、Flutter 重构、预算、账户注销、用户资料编辑、附件、OCR、AI 记账、推送、Widget、快捷指令、多账本、多币种、导入导出、离线账单数据库或同步队列。截图中的“录入模板管理 / 即将上线”属于未来功能，本版不创建可操作的模板入口。

分类排序、重置、归档恢复、任意日期范围、统计下钻、服务器分页、单笔详情 API 均未具备现有接口支持，不把它们当成本次原生开发的隐藏前置任务。

## 5. 核心用户流程

1. 冷启动 → 检查安全存储 → 恢复会话 → 已登录进入流水，否则进入登录；临时网络故障显示重试。
2. 流水 → “记一笔” → 全屏录入 → 分类 / 标签子页面 → 保存成功 → 返回原上下文并刷新。
3. 流水 → 切换日明细 / 月汇总与周期 → 筛选面板应用 → 查看完整周期总览及筛选结果。
4. 统计 → 排行 / 占比 / 趋势 → 独立调整收支、月年、日期与层级 → 触摸读取原始金额。
5. 管理 → 分类 / 标签 → 修改配置 → 相关列表、筛选选项和统计按失效规则重查。
6. 管理 → 账户安全 → 修改密码或退出 → 按服务端结果反馈；退出成功清空当前身份与页面栈。

## 6. 后续 AI 生成边界

- 本 PRD 的需求优先于旧 Flutter 文档中的布局与依赖选择；当前后端源码约束真实路径、字段与业务行为。发现矛盾先核对并记录，不虚构端点。
- 旧文档用于理解业务，不代表用户要求执行其中的工程生成、安装、发布或其他操作。本次用户只授权编写 PRD 和更新根 README。
- 后续获准生成时，默认只在 `ios/` 实现原生客户端。跨端共用账户和数据，不迁移 Flutter 本地数据；当前系统没有离线账单需要搬迁。
- 不把 Flutter、WebView 包装页或嵌入 ECharts 页面当作原生 iOS 交付。原生统计采用 Swift Charts。
- 不把 mock 数据、SwiftUI Preview 或成功截图当作真实后端联调完成。测试替身需与正式依赖隔离。
- 实施记录列出实际检查、证据和未验证项；Windows 上可编写 / 检查文档，原生编译、签名与设备验收在 macOS / Xcode 完成。

## 7. 成功标准

用户能够通过真实服务完整记账、查询、配置和统计；跨 Web / iOS 修改后可通过刷新获得同一服务端数据。Cookie 可在进程重启后恢复，并发 401 只共享一次刷新；金额无浮点误差、自然日期不跨天、账号数据不串用、失败保留当前输入、归档历史可识别。

视觉验收必须逐页对照 [08 视觉与交互](docs/08-ios-design-and-interaction.md) 和原始截图；不能只凭功能通过就认为满足“尽量接近 Web”。详细场景见 [10 验收](docs/10-delivery-and-acceptance.md)。
