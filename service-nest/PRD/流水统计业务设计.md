## 流水统计

流水统计页面用于查看当前用户在指定自然月或自然年内的分类金额排行、分类金额占比和收支变化。页面从左到右横向展示“分类排行”“分类占比”“收支趋势”三个板块，布局与视觉风格参考当前项目的配置管理页面。

三个板块的用途：

| 板块 | 业务目的 | 展示方式 |
| --- | --- | --- |
| 分类排行 | 比较所选周期内各个分类的汇总金额，支持金额升序和降序 | 分类列表、金额及占比 |
| 分类占比 | 查看所选周期内各个分类占总金额的比例 | 左侧饼图、右侧分类图例 |
| 收支趋势 | 查看所选周期内金额随日期或月份的变化，并与上一周期比较 | 周期总金额、涨跌信息及柱状图 |

三个板块分别维护自己的流水类型、统计周期和所选日期。分类排行与分类占比还分别维护分类层级，分类排行额外维护排序方向；任何一个板块的条件变化都只刷新该板块。

第一版只统计支出或收入，不提供“全部”类型、收支混合占比或结余统计。页面不展示单笔流水的标题、标签和备注，不提供新增、编辑或删除流水的操作。

## 统计口径

### 有效流水与分类

1. 所有统计只查询当前登录用户的数据。流水、流水实际绑定的分类及支出分类的父分类都必须属于当前用户。
2. 流水的 `archived_time` 必须为NULL。已删除或已归档的流水不参与分类排行、分类占比、收支趋势、总金额、流水笔数和上一周期金额的计算。
3. 流水实际绑定的分类的 `archived_time` 必须为NULL。分类已归档时，其关联流水即使尚未归档，也不参与本页任何统计。
4. 支出实际绑定的是二级分类，还必须检查其父级一级分类：二级分类或父级一级分类中任意一个已归档，都排除该笔支出。该规则同时适用于一级分类汇总、二级分类汇总和收支趋势。
5. 收入实际绑定的是一级分类，只查询未归档的收入一级分类及其有效流水。
6. 分类归档状态以查询时的当前状态为准，不按流水发生时的分类状态还原。分类归档后，重新查询以前的月份或年份时，其关联金额也会被排除；分类恢复有效后，满足其他条件的流水重新参与统计。
7. 本页统计口径与流水列表页保留已归档分类的历史关联信息的规则不同。本文件只定义流水统计页面，不修改流水列表页已有的历史展示与查询规则。
8. 本页不使用标签筛选，不需要关联标签表或流水与标签关联表。统计时不能因无关的一对多关联重复累计同一笔流水。

### 日期与分类汇总

1. 使用流水的实际发生日期 `occurredDate` 作为统计日期，沿用现有实体与数据库映射，不使用创建时间或更新时间，不修改已有日期字段。
2. 月周期统计完整自然月，年周期统计完整自然年。日期范围统一使用“包含开始日期、不包含下一周期开始日期”的方式。
3. 查询 `2026-10` 时，日期范围为 `[2026-10-01, 2026-11-01)`；查询 `2026` 时，日期范围为 `[2026-01-01, 2027-01-01)`。
4. 支出按一级分类展示时，将该一级分类下所有符合有效数据条件的二级分类流水金额汇总。按二级分类展示时，分别汇总每个二级分类的流水金额。
5. 收入只按一级分类汇总，收入请求二级分类属于无效参数。
6. 分类层级表示汇总粒度，不是选择某个具体分类的筛选条件。同一用户、类型、周期下，切换一级或二级分类时，总金额和流水笔数保持一致。
7. 分类按照分类ID识别和聚合，不按照名称聚合。不同父分类下的同名二级分类必须分别返回，并携带父分类信息用于区分。
8. 分类名称、图标与父子关系使用当前分类配置，不保存或还原历史配置快照。二级分类的图标背景色继续继承其父级一级分类的图标背景色。
9. 分类排行与分类占比只返回所选周期内有有效流水的分类，不返回零金额分类。总金额为零时，分类列表为空数组。
10. `transactionCount` 表示符合统计条件的流水记录笔数，不是分类数量；同一笔支出不能因同时关联一级和二级分类而重复计数。
11. 同一用户、类型和周期下，所有分类金额之和必须等于总金额。分类排行与分类占比的结果口径一致，排序不会改变金额或占比。
12. 收支趋势按发生日期升序返回。月周期补齐该月全部自然日期，年周期补齐1月至12月；没有有效流水的日期或月份返回金额 `"0.00"`。
13. 当前月或当前年也返回完整自然周期的时间轴，不按今天截断。未发生流水的时间位置补零，已经录入且符合条件的流水按其发生日期正常统计。

### 金额与百分比

1. 第一版只支持人民币。流水金额、分类汇总金额、本期总金额和上一周期总金额均以保留两位小数的十进制字符串传输，例如 `"1200.00"`。
2. 后端使用数据库DECIMAL运算或整数“分”进行金额比较、汇总和差额计算，不使用JavaScript浮点数直接计算金额。
3. 分类占比按 `分类汇总金额 / 当前周期总金额 × 100` 计算。响应中的 `percentage` 使用保留两位小数的字符串，不包含百分号；`"12.50"` 表示12.50%，不是0.125。
4. 分类占比使用精确金额计算，最终结果四舍五入保留两位小数。各分类显示占比之和可能因舍入产生小幅误差，不调整某个分类占比来强制凑成100%。
5. 分类排行和分类占比文案的分母是当前统计条件下全部有效流水的总金额，不是当前可见行、前三名或某一父分类的金额。
6. 收支趋势图中所有时间点金额之和必须等于本期总金额。同一用户、类型和周期下，其总金额也必须与分类排行及分类占比一致。

## 后端业务逻辑

### 流水统计模块

流水统计模块目录命名为 `statistics`。本次不新增数据库表，不增加金额汇总快照表或统计持久化字段；直接查询现有流水、用户分类及分类图标数据。

对外保留六个独立GET查询接口。分类排行、分类占比和收支趋势分别提供月查询与年查询，公共查询条件与计算逻辑在模块内部复用。

| 业务操作 | Service方法 | HTTP接口 | 必填查询参数 |
| --- | --- | --- | --- |
| 分类排行按月查询 | `findMonthlyCategoryRanking(userId, month, type, categoryLevel, order)` | `GET /statistics/category-ranking/monthly` | `month`、`type`、`categoryLevel`、`order` |
| 分类排行按年查询 | `findYearlyCategoryRanking(userId, year, type, categoryLevel, order)` | `GET /statistics/category-ranking/yearly` | `year`、`type`、`categoryLevel`、`order` |
| 分类占比按月查询 | `findMonthlyCategoryProportion(userId, month, type, categoryLevel)` | `GET /statistics/category-proportion/monthly` | `month`、`type`、`categoryLevel` |
| 分类占比按年查询 | `findYearlyCategoryProportion(userId, year, type, categoryLevel)` | `GET /statistics/category-proportion/yearly` | `year`、`type`、`categoryLevel` |
| 收支趋势按月查询 | `findMonthlyTransactionTrend(userId, month, type)` | `GET /statistics/transaction-trend/monthly` | `month`、`type` |
| 收支趋势按年查询 | `findYearlyTransactionTrend(userId, year, type)` | `GET /statistics/transaction-trend/yearly` | `year`、`type` |

统一身份与响应规则：

1. `userId` 由Controller从登录凭证解析后的认证上下文获取，再传给Service，不作为客户端提交的路径参数、查询参数或请求体字段。
2. Controller使用DTO校验查询参数，Service接收用户ID和各个已校验的具体业务参数，不直接接收查询DTO。
3. 所有接口沿用项目已有认证、异常处理和统一响应包装，不重复包装 `data`。以下响应类型与示例均表示统一响应中的 `data` 内容。
4. 查询成功但没有有效流水时仍返回200及完整结构，不返回404，不返回NULL。
5. 六个接口均为只读查询，不创建、修改、归档或删除任何业务数据。

### DTO与参数校验

#### 通用参数

| 参数 | 类型与取值 | 说明 |
| --- | --- | --- |
| `type` | `expense` / `income`，必填 | 复用现有流水类型枚举，不支持 `all` |
| `categoryLevel` | `1` / `2`，分类排行与分类占比必填 | 分类汇总层级；内部转换为数值1或2，替代含义不明确的 `categoryType` |
| `month` | `YYYY-MM` 字符串，月查询必填 | 完整自然月，例如 `2026-10` |
| `year` | `YYYY` 字符串，年查询必填 | 完整自然年，例如 `2026`，不使用 `month` 字段保存年份 |
| `order` | `asc` / `desc`，分类排行必填 | 金额升序或降序；默认值由前端明确传入 `desc` |

参数规则：

1. `type`、`categoryLevel` 和 `order` 只能使用规定的枚举值。必填参数缺失、空字符串、非法数组或格式不正确时返回400。
2. HTTP查询中的 `categoryLevel` 只接受 `1` 或 `2`，不得通过宽松数值转换接受其他写法；`type = income` 且 `categoryLevel = 2` 时返回400，提示“收入只支持一级分类统计”。后端不静默修改非法参数。
3. `month` 必须是四位有效年份和两位月份，月份只能为01至12；拒绝 `2026-1`、`2026-00`、`2026-13` 等值。`year` 必须是有效的四位年份，拒绝 `0000` 等无效值。
4. 查询周期、上一比较周期及计算日期范围所需的边界日期必须在现有数据库支持的日期范围内，超出范围时返回400，不产生无效日期查询。
5. 月查询只接收 `month`，年查询只接收 `year`，不能同时提交两种周期参数。年查询请求不携带空的 `month` 字段，月查询请求不携带空的 `year` 字段。
6. 分类占比不接收 `order`；收支趋势不接收 `categoryLevel` 或 `order`。
7. 第一版不接收具体分类ID、标签、标题、备注、金额区间、分页或自定义日期范围参数。对不属于当前接口的查询字段返回400，不静默应用或忽略。

#### DTO复用关系

1. 类型查询基类只定义 `type`。分类汇总查询基类在此基础上增加 `categoryLevel`，避免趋势接口继承不需要的分类参数。
2. 分类汇总按月DTO增加 `month`，按年DTO增加 `year`，分类占比的两个接口直接使用对应DTO。
3. 分类排行按月和按年DTO分别继承对应分类汇总DTO，再增加必填的 `order`。
4. 趋势按月和按年DTO分别在类型查询基类上增加 `month` 或 `year`，不继承分类汇总DTO。
5. 每个公开接口只暴露其业务需要的参数，复用DTO时仍校验跨字段约束。

### 公共查询与计算逻辑

1. 提取自然月、自然年、上一月、上一年的日期范围计算方法。1月的上一月为上一年12月，年比较目标为查询年份减1。
2. 提取有效流水基础条件，统一包含当前用户、收支类型、流水未归档、实际分类未归档以及支出父分类未归档等约束。所有本期查询与上一周期查询都使用这套条件。
3. 分类排行与分类占比共用分类聚合方法，根据 `categoryLevel` 选择一级或二级分类ID进行分组，计算金额、流水笔数和占比，再分别执行各自的排序规则。
4. 收支趋势共用按时间聚合及补齐时间轴的方法，月查询按日聚合，年查询按月聚合；本期与上一周期的总金额共用有效流水金额汇总逻辑。
5. 分类汇总与时间汇总优先在数据库中聚合，不为统计加载整个周期的单笔流水及其标签、标题和备注。
6. 总金额、流水笔数和列表应来自同一有效记录集合。同一响应需要多次查询时，使用一致的读取结果或读快照，避免并发写入造成列表金额之和与总金额不一致。
7. 查询只根据业务参数选择分组与排序，不把客户端输入直接拼接为SQL字段或排序表达式。
8. 六个接口保留独立Controller入口和Service业务方法；日期范围、有效数据条件、分类聚合、精确金额及百分比计算在内部复用。

### 公共分类统计响应结构

分类排行与分类占比共用分类统计结构。列表项本身代表一个分类的汇总结果，不代表单笔流水，因此使用 `items`，不使用 `transactions`。

```ts
type StatisticsPeriodType = 'month' | 'year';

interface StatisticsParentCategory {
  categoryId: number;
  name: string;
}

interface CategoryStatisticsItem {
  categoryId: number;
  name: string;
  iconKey: string;
  backgroundColor: string;
  parent: StatisticsParentCategory | null;
  amount: string;
  percentage: string;
}

interface CategoryStatisticsResult {
  period: string;
  periodType: StatisticsPeriodType;
  type: TransactionType;
  categoryLevel: 1 | 2;
  transactionCount: number;
  totalAmount: string;
  items: CategoryStatisticsItem[];
}

interface CategoryRankingResult extends CategoryStatisticsResult {
  order: 'asc' | 'desc';
}
```

字段规则：

| 字段 | 说明 |
| --- | --- |
| `period` | 所选月份或年份，月为 `YYYY-MM`，年为 `YYYY` |
| `periodType` | 所选周期类型，`month` 或 `year` |
| `type` | 当前统计的流水类型，复用现有 `TransactionType` |
| `categoryLevel` | 本次采用的分类汇总层级 |
| `transactionCount` | 当前周期符合条件的流水笔数，整数；没有数据时为0 |
| `totalAmount` | 当前周期、当前类型的有效流水总金额 |
| `items[].categoryId` | 当前汇总分类的ID，也是列表项的唯一身份；不增加流水ID或重复的分类ID字段 |
| `items[].name` | 当前汇总分类名称 |
| `items[].iconKey` | 当前汇总分类使用的图标键 |
| `items[].backgroundColor` | 图标最终背景色；二级分类继承父级，不作为饼图扇区配色 |
| `items[].parent` | 二级支出分类返回父分类ID和名称；一级支出分类和收入分类为NULL |
| `items[].amount` | 该分类在当前周期的有效流水金额之和 |
| `items[].percentage` | 该分类金额占 `totalAmount` 的百分比，两位小数字符串，不含 `%` |
| `order` | 仅分类排行响应返回，表示当前生效的金额排序方向 |

### 分类排行查询

#### 分类排行按月查询

`GET /statistics/category-ranking/monthly` 查询一个完整自然月。请求示例：

```text
GET /statistics/category-ranking/monthly?type=expense&categoryLevel=2&month=2026-10&order=desc
```

1. 接收必填的 `type`、`categoryLevel`、`month` 和 `order`。
2. 按当前分类层级聚合有效流水金额，返回 `CategoryRankingResult`，`periodType` 为 `month`。
3. `order = desc` 时按照分类汇总金额降序、分类ID升序排序；`order = asc` 时按照分类汇总金额升序、分类ID升序排序。
4. 金额排序使用精确数值比较，不能按金额字符串字典序排序。金额相同时，两种排序方向都固定按分类ID升序。
5. 返回全部有金额的分类，不分页、不截取前三或前十，不在响应中返回排名序号；前端根据返回顺序生成序号。
6. 没有有效流水时返回 `transactionCount = 0`、`totalAmount = "0.00"`、`items = []`，仍返回所选周期、类型、层级与排序。

#### 分类排行按年查询

`GET /statistics/category-ranking/yearly` 查询一个完整自然年。请求示例：

```text
GET /statistics/category-ranking/yearly?type=expense&categoryLevel=1&year=2026&order=desc
```

接收必填的 `type`、`categoryLevel`、`year` 和 `order`，返回 `CategoryRankingResult`，`periodType` 为 `year`。整个年份按分类合并汇总，不按月份拆成多个排行榜；其余汇总、排序和空结果规则与月查询一致。

### 分类占比查询

#### 分类占比按月查询

`GET /statistics/category-proportion/monthly` 查询一个完整自然月。请求示例：

```text
GET /statistics/category-proportion/monthly?type=expense&categoryLevel=2&month=2026-10
```

1. 接收必填的 `type`、`categoryLevel` 和 `month`，不接收排序参数。
2. 返回 `CategoryStatisticsResult`，`periodType` 为 `month`，不返回 `order`。
3. 列表固定按分类汇总金额降序、分类ID升序排列。前端图例与饼图均使用该顺序。
4. 与相同条件下的分类排行使用完全相同的有效数据、总金额、流水笔数、分类金额与占比。
5. 返回全部有金额的分类，不自动合并成“其他”扇区，也不截取前几项；用户自己创建的“其他”分类作为普通分类处理。
6. 没有有效流水时返回 `transactionCount = 0`、`totalAmount = "0.00"`、`items = []`。

#### 分类占比按年查询

`GET /statistics/category-proportion/yearly` 查询一个完整自然年。请求示例：

```text
GET /statistics/category-proportion/yearly?type=income&categoryLevel=1&year=2026
```

接收必填的 `type`、`categoryLevel` 和 `year`，返回 `CategoryStatisticsResult`，`periodType` 为 `year`。以整个年份的有效分类金额作为占比计算基础，其余规则与月查询一致。

### 收支趋势查询

#### 比较规则

1. 月趋势的 `totalAmount` 是所选完整自然月的总金额，`previousTotalAmount` 是上一个完整自然月的总金额；例如 `2026-10` 与 `2026-09` 比较。
2. 年趋势的 `totalAmount` 是所选完整自然年的总金额，`previousTotalAmount` 是上一个完整自然年的总金额；例如 `2026` 与 `2025` 比较。
3. 无论查询当前月、当前年还是历史周期，都按上述完整自然周期比较，不按具体日期截取同期，不增加“截至今天”“上月同日”或“去年同日”的比较口径。
4. 本期和上一期必须使用相同用户、相同流水类型及相同有效数据条件，均排除已归档流水、已归档实际分类和已归档支出父分类。
5. 上一期总金额大于零时，`changeRate = (totalAmount - previousTotalAmount) / previousTotalAmount × 100`，最终四舍五入保留两位小数。
6. `changeRate` 是有符号的百分比字符串，不带 `%`；增加示例为 `"25.00"`，减少示例为 `"-25.00"`。为零时统一返回 `"0.00"`，不返回负零。
7. `changeStatus` 根据两期精确金额的比较确定，不根据舍入后的百分比判断方向。

| 本期与上一期金额 | `changeStatus` | `changeRate` | 前端含义 |
| --- | --- | --- | --- |
| 上一期大于零，本期大于上一期 | `increase` | 正百分比，极小变化舍入后可能为 `"0.00"` | 增加 |
| 上一期大于零，本期小于上一期 | `decrease` | 负百分比；本期为零时为 `"-100.00"` | 减少 |
| 两期相等，包括都为零 | `unchanged` | `"0.00"` | 持平 |
| 上一期为零、本期大于零 | `new` | NULL | 新增金额，不能计算有限涨幅 |

#### 趋势响应结构

```ts
interface TransactionTrendPoint {
  date: string;
  amount: string;
}

interface TransactionTrendResult {
  period: string;
  periodType: StatisticsPeriodType;
  type: TransactionType;
  transactionCount: number;
  totalAmount: string;
  previousPeriod: string;
  previousTotalAmount: string;
  changeRate: string | null;
  changeStatus: 'increase' | 'decrease' | 'unchanged' | 'new';
  series: TransactionTrendPoint[];
}
```

字段规则：

1. `period`、`periodType`、`type`、`transactionCount` 与 `totalAmount` 的含义与分类统计一致。
2. `previousPeriod` 返回实际比较周期，月为 `YYYY-MM`，年为 `YYYY`；`previousTotalAmount` 使用两位小数字符串。
3. `changeRate` 仅在 `changeStatus = new` 时为NULL。不得返回Infinity、NaN、百分号或以 `"0.00"` 代替无法计算的涨幅。
4. 月查询的 `series[].date` 为完整日期 `YYYY-MM-DD`，年查询为完整月份 `YYYY-MM`。后端不返回“1日”“1月”等展示文案。
5. 月查询返回该月全部28、29、30或31个时间点，正确处理闰年；年查询固定返回12个时间点。所有时间点按日期升序排列。
6. 本期没有有效流水时，`transactionCount = 0`、`totalAmount = "0.00"`，但 `series` 仍完整返回并全部补零；上一周期金额与比较结果仍按真实统计返回。

#### 收支趋势按月查询

`GET /statistics/transaction-trend/monthly` 查询一个完整自然月。请求示例：

```text
GET /statistics/transaction-trend/monthly?type=expense&month=2026-10
```

接收必填的 `type` 和 `month`，返回 `TransactionTrendResult`，`periodType` 为 `month`。`series` 返回该月每日有效金额；查询2026年10月时，时间点从 `2026-10-01` 到 `2026-10-31`。比较目标为2026年9月完整自然月。

#### 收支趋势按年查询

`GET /statistics/transaction-trend/yearly` 查询一个完整自然年。请求示例：

```text
GET /statistics/transaction-trend/yearly?type=income&year=2026
```

接收必填的 `type` 和 `year`，返回 `TransactionTrendResult`，`periodType` 为 `year`。`series` 返回该年每月有效金额；查询2026年时，时间点从 `2026-01` 到 `2026-12`。比较目标为2025年完整自然年。

### 图表实现与依赖

1. Web端统一使用 Apache ECharts 实现分类占比饼图和收支趋势柱状图，固定版本为 `6.1.0`。`web/package.json` 中声明 `"echarts": "6.1.0"`，不使用 `^`、`~` 或 `latest`；同步提交 `package-lock.json`，确保安装结果可复现。后续升级需同时更新本PRD、依赖声明及锁文件，并重新验证统计页面。
2. 通过 `echarts/core` 按需注册 `PieChart`、`BarChart`、`TooltipComponent`、`GridComponent`、`AriaComponent` 和 `CanvasRenderer`，避免全量引入。饼图使用 `pie` 系列，内半径为0，趋势使用 `bar` 系列与直角坐标系，不再手工绘制SVG扇区、柱子、坐标轴和网格线。分类排行使用分类行展示排名、图标、名称、金额和占比。
3. 每个图表组件分别管理自己的ECharts实例，在容器具备有效宽高后初始化。响应变化后通过 `setOption` 完整替换配置，清除旧周期的图形和Tooltip，不能因为分类数量减少、月／年切换或空数据而保留旧扇区、柱子或轴标签。
4. 使用 `ResizeObserver` 监听图表容器尺寸变化并调用实例 `resize()`，覆盖浏览器缩放、卡片可用高度变化及横向布局调整。页面或组件卸载时断开尺寸监听、移除相关事件监听并调用 `dispose()`；条件更新不重复创建图表实例。
5. 图表Tooltip使用ECharts能力，HTML浮层挂载到 `document.body`，位置限制在可见视口内，避免被卡片滚动区域裁切。分类自身名称按纯文本展示，不附加父分类路径，不能将用户输入直接拼接为未转义HTML。图例悬停或键盘聚焦通过 `dispatchAction` 联动对应扇区的高亮与Tooltip，离开或取消聚焦时清除高亮及浮层。
6. ECharts仅负责可视化。扇区及柱子绘制时可将接口金额字符串转换为数值；总额、涨跌信息、金额Tooltip及分类百分比文案继续使用后端精确字符串，不使用图表内部计算的百分比替代 `percentage`。扇区颜色仍按分类ID稳定生成，左侧饼图区域左上方的总金额继续使用精确金额格式化展示。
7. 保留完整零值趋势时间轴和可读默认Y轴刻度；分类占比为空时展示既定空态，不绘制虚假的100%扇区。图表容器提供可访问名称及完整数据说明，图例保留键盘操作。

8. 鼠标悬停扇区时只展示分类自身名称、金额及百分比；二级分类不附加一级父分类名称。悬停图例或键盘聚焦时显示相同信息，并高亮对应扇区。图表和图例依旧以分类ID区分同名分类。
9. 图例文字过长时单行省略，通过Tooltip显示完整的分类自身名称，不显示父分类路径；扇区与图例之间不得因名称过长产生遮挡。
10. 当前版本不增加参考图中的“查看详情”入口或分类下钻操作。

### 收支趋势

#### 顶部筛选区域

从左到右为收支类型、月／年切换图标按钮、日历图标按钮。周期按钮、日历按钮的颜色、布局和日期选择规则与其他板块一致，按钮旁不展示具体年月，不提供分类层级或排序按钮。

#### 总额与比较信息

1. 图表区域上方先显示“支出总额”或“收入总额”，下一行显示本期总金额。金额使用人民币符号、千位分隔符和两位小数，字号明显大于普通行金额，并加粗。
2. 比较信息位于总金额右侧；卡片宽度不足时允许换到下一行，不能覆盖金额或截断比较文案。
3. 月周期比较文案为“较上月”，年周期为“较上年”，展示规则如下。

| 状态 | 月周期文案示例 | 年周期文案示例 |
| --- | --- | --- |
| 增加 | `较上月 ↑ 25.00%` | `较上年 ↑ 25.00%` |
| 减少 | `较上月 ↓ 25.00%` | `较上年 ↓ 25.00%` |
| 持平 | `较上月持平 0.00%` | `较上年持平 0.00%` |
| 上一期为零、本期大于零 | `较上月新增` | `较上年新增` |

4. 前端根据 `changeStatus` 判断箭头与文案，正常涨跌显示 `changeRate` 的绝对值，不同时显示下降箭头与负号。
5. 比较信息颜色遵循以下规则，不使用“增益”“负收益”描述支出变化。

| 类型 | 增加或新增 | 减少 | 持平 |
| --- | --- | --- | --- |
| 支出 | 绿色 `#249E68`、增加时使用↑ | 红色 `#E34D59`、使用↓ | 中性色 |
| 收入 | 红色 `#E34D59`、增加时使用↑ | 绿色 `#249E68`、使用↓ | 中性色 |

6. `new` 状态不显示无法计算的百分比，不显示100%、Infinity或NaN；本期无数据但上一期有数据时，仍显示下降100.00%。

#### 柱状图

1. 使用ECharts `bar` 系列绘制竖向柱状图，X轴为日期或月份，Y轴为金额，不使用参考图中的折线图。
2. 月周期使用完整每日时间点，按顺序对应“1日”至该月最后一天；年周期使用完整12个月，按顺序对应“1月”至“12月”。
3. 后端返回完整日期或月份，前端负责生成本地化横轴文案。月图较窄时可以间隔展示横轴标签，但必须保留所有时间点和柱子。
4. 无流水的日期或月份保留零值位置，不删除时间点。整期金额为零时保持完整时间轴，Y轴使用可读的默认刻度，不出现无效最大值。
5. 柱子采用当前主题色，网格线、坐标轴与说明文字采用项目现有中性色；悬停时突出当前柱子。
6. 鼠标悬停某个时间点时显示完整日期或月份及该点金额，金额保留两位小数。窄卡片上的Tooltip不得被局部滚动容器裁切。
7. Y轴可以为大金额使用“万”等简写单位，Tooltip和顶部总金额仍显示完整金额，不能把轴刻度简写当作金额数据。
8. 图表宽高随卡片可用区域调整，保证顶部筛选、总金额和比较信息可见，不因31个日期产生超出卡片的内容。

### 请求与页面状态

#### 加载与刷新

1. 每个板块独立提供首次加载、条件切换加载、查询失败、空数据和重新加载状态。
2. 首次加载使用项目现有加载组件或占位骨架，不把加载中展示为零金额空态。
3. 条件变化后立即标记旧结果与新条件不一致，展示本板块的刷新状态；可保留旧结果作为过渡，但必须说明“刷新中，显示上次结果”，不得把旧数据误标为新周期或新类型。
4. 连续切换条件时取消旧请求或使用递增请求序号，只接受当前条件对应的最新响应；旧响应、旧错误和旧请求结束状态不得覆盖新请求结果。
5. 收入强制切换一级、周期与日期转换等联动操作完成后只发起一次查询，不发送中间非法条件。
6. 重新加载只请求失败板块的当前条件，不重置该板块筛选，不刷新其他板块。
7. 页面离开时取消未完成请求或忽略其结果，防止已销毁页面继续更新状态。

#### 空数据与错误

1. 分类排行无数据时显示现有空数据图标 `icon-queshengye_zanwushuju` 及“所选周期暂无有效支出记录”或“所选周期暂无有效收入记录”，不生成空分类行。
2. 分类占比无数据时显示相同空态，保留总金额 `¥ 0.00`，不绘制虚假的100%扇区。
3. 收支趋势无数据时，总金额为 `¥ 0.00`，图表保留完整零值时间轴，可附“所选周期暂无有效记录”；比较信息继续按上一周期金额展示。
4. 本页不为已归档流水或分类提供显示开关，不在空态中展示被排除的分类，也不提供新增分类或新增流水的操作入口。
5. 首次查询失败时展示错误说明与“重新加载”入口，不显示伪造金额；刷新失败时可以保留上次成功结果，并明确提示“刷新失败，显示上次结果”。
6. 保留旧结果时，结果对应的日期、类型和分类层级必须可以辨认。错误提示不能导致其他板块已成功数据消失。
7. 卡片内金额、分类名称、图例和Tooltip均需处理长内容，不能挤压排序、日历或占比区域。

## 与现有业务的衔接

1. 页面入口与应用布局沿用当前统计页；卡片布局参考配置管理页，类型切换、周期按钮和单选日期选择器参考流水页。
2. 图标、金额格式化、登录认证、HTTP封装、统一响应和错误提示复用项目已有能力，统计页自己的条件与请求状态独立维护。
3. 后端沿用现有流水实体、用户分类实体、分类图标实体及收支类型枚举；无需新表、数据迁移或修改流水保存规则。
4. 本页对已归档分类的排除规则以本文件为准，不能直接复用流水列表查询中“保留历史归档分类”的条件；复用公共工具时必须保留两个页面各自明确的业务口径。
5. 用户在其他页面新增、编辑、删除流水，或修改、归档、恢复分类后，统计页下一次加载或刷新按最新数据重新计算，不展示永久缓存的统计快照。

## 实现与注释要求

1. 本次流水统计功能实现中新增或修改的所有前后端方法与函数都必须编写JSDoc注释，覆盖Controller、Service、构造方法、公共工具、前端API方法、composable及组件事件处理方法。
2. JSDoc使用 `/** ... */` 格式，以中文说明方法用途和业务含义；使用 `@param` 说明每个参数，使用 `@returns` 说明返回结果，存在明确异常时使用 `@throws` 说明异常条件。异步方法需说明异步返回结果，涉及金额、日期、百分比或归档规则时写明对应格式、单位与约束。
3. 所有逻辑在关键节点必须添加中文注释，说明处理目的、业务规则和边界情况。包括用户归属与归档校验、自然周期及上一周期计算、分类聚合与排序、金额精度与占比计算、上期金额为零的处理、时间轴补零、筛选条件联动、图表稳定配色、请求竞态控制及加载失败时保留旧结果等节点。
4. 方法级JSDoc与关键节点注释需同时提供。注释应帮助理解“为什么这样处理”和数据如何变化；修改逻辑时同步更新注释，保持注释与实际行为一致。

## 验收要点

1. 三个板块横向并排，间距、圆角、主题与当前项目一致，窄屏可横向滚动；排行与图例的纵向滚动互不影响。
2. 三个板块首次默认查询当前月支出；排行和占比默认二级分类，排行默认金额降序。修改任一板块条件只刷新该板块。
3. 六个接口均从登录上下文取得用户ID，不能查询其他用户的流水或分类；收入二级分类、错误月份、错误年份及不支持的参数返回400。
4. 已归档流水、已归档实际分类和已归档支出父分类均被排除，排除规则覆盖总额、笔数、分类项、趋势时间点以及上一周期金额。
5. 一级与二级支出汇总切换时总金额和流水笔数一致；一级分类金额等于其有效二级分类金额之和。同名但不同ID的分类分别统计。
6. 排行按精确金额排序，金额相同按分类ID升序；序号由返回顺序生成，前三按当前顺序强调，升序时代表最小的三个分类。
7. 同一条件下排行与占比金额、笔数和占比一致；全部分类金额之和、趋势所有时间点金额之和分别等于同一周期的总金额。
8. 月趋势包含完整自然月日期，正确覆盖28、29、30、31天和闰年；年趋势固定12个月，缺少流水的时间点补零。
9. 月趋势与上一个完整自然月比较，年趋势与上一个完整自然年比较；当前周期也采用整期口径，1月能正确比较上一年12月。
10. 两期为零、两期相等、上一期为零本期新增、本期为零上一期有金额以及普通涨跌均有正确金额、状态、百分比、箭头和颜色。
11. 饼图配色与图标背景色分别处理，同一父分类下的二级分类可区分，同一分类跨周期保持稳定配色，图例与扇区一致。
12. 空数据、首次加载失败、刷新失败与快速连续切换都有明确状态；旧响应不会覆盖最新条件，失败板块可独立重新加载。
13. 本次实现涉及的所有新增或修改方法与函数均有符合JSDoc规范的注释，关键逻辑节点有中文说明，参数、返回结果、业务规则及边界处理与实际代码一致。
14. ECharts版本固定为 `6.1.0`，依赖声明与锁文件一致；饼图、柱状图、坐标轴、网格线、高亮和图表Tooltip由ECharts实现，分类排行使用单行列表，不展示进度条。
15. 图表尺寸变化后正确适配；数据切换不残留旧图形和浮层；组件卸载后ECharts实例、尺寸监听及相关事件均被清理。图例和扇区高亮联动正确，长名称以纯文本展示，窄屏Tooltip不超出视口或被局部滚动裁切。
