## 要求

1. 一笔支出一定要绑定且只能绑定一个二级分类，不绑定一级分类，通过二级分类来判断它的一级分类归属。标签和事件非必须。
2. 收入只选一级分类
3. 查询数据时，一级分类、二级分类、标签、事件都可以做筛选条件，二级分类的列表取值受一级分类影响
4. 分类按来源分为默认来源分类和用户自定义分类两种，但用户实际使用的分类都属于当前用户，均可编辑、归档和排序。
   - 默认来源分类
     系统通过默认分类模板为新用户初始化分类。初始化后生成的是该用户自己的分类副本，用户可以修改名称、图标和顺序，也可以归档。分类通过 `source_template_id` 保留其默认模板来源，用于执行分类重置。
   - 用户自定义分类
     用户可自行添加一级分类、二级分类，包括名称、图标和展示顺序调整。用户自定义分类的 `source_template_id` 为NULL。
   - 分类重置
     重置时归档用户自定义分类，将默认来源分类的名称、图标、层级、父子关系、顺序和归档状态恢复为当前默认分类模板；整个过程不得破坏历史金额记录的分类关联。
5. 标签、事件没有默认，用户可创建、编辑、删除
   - 一笔金额可以有多个标签，一个标签也可以被多笔金额使用，即多对多。
   - 一笔金额只能有一个事件，但是一个事件可以有多笔金额。比如2026年9月21日去游乐园玩，除了门票钱，可能在游乐园内购买了零食，回去途中又选择了打车，所以这个事件涉及到了3笔消费：门票、零食、交通出行，所以设定事件为一对多。

## 默认分类模板表

category_template

默认分类模板只作为用户分类初始化和重置的基准，不直接关联金额记录，也不直接返回给普通用户使用。

| 字段          | 类型与要求                                                              | 说明                                             |
| ------------- | ----------------------------------------------------------------------- | ------------------------------------------------ |
| id            | INT AUTO_INCREMENT PRIMARY KEY                                          | 模板主键                                         |
| type          | VARCHAR(20) NOT NULL，取值仅限 expense / income                         | 分类所属的金额类型                               |
| parent_id     | INT NULL，FK -> category_template.id，ON DELETE RESTRICT                | 父级模板id；一级分类模板为NULL                   |
| name          | VARCHAR(50) NOT NULL                                                    | 默认分类名称                                     |
| default_sort  | INT NOT NULL DEFAULT 0，值不得小于0                                     | 初始化或重置用户分类时使用的默认顺序             |
| level         | TINYINT NOT NULL，取值仅限1或2                                          | 分类层级                                         |
| icon_key      | VARCHAR(100) NOT NULL                                                   | 默认图标资源标识，不允许为NULL                   |

默认分类模板表约束：

1. `level = 1` 时 `parent_id` 必须为NULL；`level = 2` 时 `parent_id` 必须非NULL。
2. `type = income` 时只允许一级分类模板；支出允许一级、二级分类模板。
3. 二级分类模板的父模板必须是一级分类模板，并且父子模板的 `type` 必须相同。
4. 同一金额类型和父模板下，模板名称不能重复，由业务层校验。
5. 模板属于系统预置的静态数据，运行期只读，不提供创建、编辑、归档或删除操作。
6. `icon_key` 必须有值，不允许为NULL。
7. 建议建立索引 `INDEX(type, parent_id, default_sort)` 和 `INDEX(parent_id)`。

## 用户分类表

user_category

用户分类表存储所有归属于用户、实际参与记账的分类，包括默认分类模板初始化出的分类副本和用户自定义分类。

| 字段               | 类型与要求                                                              | 说明                                                         |
| ------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| id                 | INT AUTO_INCREMENT PRIMARY KEY                                          | 主键                                                         |
| owner_user_id      | INT NOT NULL，FK -> users.id，ON DELETE RESTRICT                       | 所属用户id；所有用户实际使用的分类都必须归属于某个用户       |
| source_template_id | INT NULL，FK -> category_template.id，ON DELETE RESTRICT               | 默认模板来源；非NULL表示默认来源分类，NULL表示用户自定义分类 |
| type               | VARCHAR(20) NOT NULL，取值仅限 expense / income                         | 分类所属的金额类型                                           |
| parent_id          | INT NULL，FK -> user_category.id，ON DELETE RESTRICT                    | 当前用户的父级分类id；一级分类为NULL                         |
| name               | VARCHAR(50) NOT NULL                                                    | 当前用户实际使用的分类名称                                   |
| sort_order         | INT NOT NULL DEFAULT 0，值不得小于0                                     | 当前用户的分类展示顺序                                       |
| level              | TINYINT NOT NULL，取值仅限1或2                                          | 分类层级                                                     |
| icon_key           | VARCHAR(100) NOT NULL                                                   | 当前用户实际使用的图标资源标识，不允许为NULL                 |
| archived_time      | DATETIME NULL                                                           | 归档时间，NULL表示未归档                                     |
| created_time       | DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP                             | 创建时间                                                     |
| updated_time       | DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间                                                     |

分类表约束：

1. `level = 1` 时 `parent_id` 必须为NULL；`level = 2` 时 `parent_id` 必须非NULL。
2. `type = income` 时只允许一级分类；支出允许一级、二级分类。
3. 二级分类的父分类必须是一级分类，父子分类的 `type` 必须相同，并且必须属于同一个用户。
4. `source_template_id` 创建后不可由普通编辑修改；同一个用户对同一个模板最多只能存在一条分类记录，建议建立 `UNIQUE(owner_user_id, source_template_id)`。MySQL允许该唯一索引存在多条 `source_template_id = NULL` 的用户自定义分类。
5. 同一用户、金额类型和父分类下，未归档的分类名称不能重复。由于MySQL唯一索引对NULL的处理方式，这条规则由业务层校验。
6. 分类删除统一采用逻辑归档，即设置 `archived_time`，不进行物理删除；已被金额记录引用的分类归档后仍需保留历史关联。
7. 归档一级分类时，如果它下面还有未归档的二级分类，则拒绝归档。用户必须先归档其下所有二级分类；分类重置作为批量业务操作时，应先归档二级分类再处理一级分类。
8. 新建用户自定义分类时，`sort_order` 默认取同一排序范围内当前最大值加1，使新分类排列在末尾；调整顺序时统一重写该范围内所有分类的 `sort_order`。
9. 默认来源分类和用户自定义分类都允许所属用户修改名称、图标、顺序和归档状态，二者仅通过 `source_template_id` 区分来源和是否可被重置。
10. `icon_key` 必须有值，不允许为NULL。
11. 建议建立索引 `INDEX(owner_user_id, type, parent_id, archived_time, sort_order)`、`INDEX(parent_id)` 和 `UNIQUE(owner_user_id, source_template_id)`。

## 金额记录关联要求

金额记录表至少需要以下分类相关字段：

| 字段        | 类型与要求                                               | 说明                               |
| ----------- | -------------------------------------------------------- | ---------------------------------- |
| category_id | INT NOT NULL，FK -> user_category.id，ON DELETE RESTRICT | 支出绑定二级分类，收入绑定一级分类 |
| event_id    | INT NULL，FK -> event.id，ON DELETE RESTRICT             | 可选事件；一笔金额最多一个事件     |

跨表业务约束：

1. 金额记录、分类、标签和事件必须属于同一个用户。默认分类模板不直接关联金额记录。
2. 支出记录的 `category_id` 必须指向 `type = expense` 的二级分类。
3. 收入记录的 `category_id` 必须指向 `type = income` 的一级分类。
4. 创建或修改金额记录时，不能选择已经归档的分类、标签或事件；历史记录仍可读取已归档数据。
5. 建议在金额记录表建立 `INDEX(category_id)` 和 `INDEX(event_id)`。

## 后端业务逻辑

### 分类模块

分类模块目录命名为 `categories`。一级分类和二级分类共用 `user_category` 表和同一个模块，不拆成两个独立模块。默认分类模板只在用户分类初始化和重置时由后端读取，不作为普通用户的分类资源直接暴露。模块对外提供以下业务方法：

统一身份约束：

1. 下列所有业务方法中的 `userId` 均表示当前登录用户id，由Controller从JWT等登录凭证解析后的认证上下文中取得，再传给Service。
2. `userId` 不作为路径参数、查询参数或请求体字段由客户端提交，避免客户端伪造其他用户id进行越权访问。
3. Service必须使用该 `userId` 查询用户可见分类，并校验分类的所属关系；不能仅依赖客户端传入的分类id。

| 业务操作         | Service方法                         | HTTP接口                 | 说明                                                               |
| ---------------- | ----------------------------------- | ------------------------ | ------------------------------------------------------------------ |
| 获取用户所有分类 | `findAllForUser(userId, query)`     | `GET /categories`        | 只查询当前用户实际拥有的分类，按 `sort_order, id` 排序             |
| 分类排序         | `reorder(userId, dto)`              | `PUT /categories/order`  | 对指定金额类型下的一级分类，或者指定父分类下的二级分类进行批量排序 |
| 创建分类         | `create(userId, dto)`               | `POST /categories`       | 创建用户自定义分类，根据 `parentId` 判断分类层级                   |
| 编辑分类         | `update(userId, categoryId, dto)`   | `PATCH /categories/:id`  | 默认来源分类和用户自定义分类都允许修改名称和图标                   |
| 删除分类         | `archive(userId, categoryId)`       | `DELETE /categories/:id` | 默认来源分类和用户自定义分类都执行逻辑归档                         |
| 重置分类         | `resetToDefaults(userId)`           | `POST /categories/reset` | 归档用户自定义分类，并按默认分类模板恢复默认来源分类               |

#### 用户分类初始化

1. 新用户创建成功后，应在事务中读取所有默认分类模板并初始化该用户的分类。也可以采用首次访问分类模块时惰性初始化，但初始化操作必须保证幂等。
2. 初始化时先复制一级分类模板，再根据模板父子关系复制二级分类模板，并将二级分类的 `parent_id` 指向该用户对应的一级分类记录。
3. 初始化生成的分类必须设置 `owner_user_id = userId`、`source_template_id = category_template.id`、`sort_order = category_template.default_sort`。
4. `UNIQUE(owner_user_id, source_template_id)` 用于防止重复初始化；初始化重试时应复用或更新已有默认来源分类，不能重复插入。
5. 默认分类模板本身不得写入金额记录的 `category_id`。

#### 获取用户所有分类

| 字段              | 是否必填 | 说明                                                |
| ----------------- | -------- | --------------------------------------------------- |
| `type`            | 否       | `expense` 或 `income`；不传时返回全部金额类型的分类 |
| `includeArchived` | 否       | 是否包含已归档分类，默认值为 `false`                |

业务要求：

1. 查询条件必须包含 `owner_user_id = userId`，不得返回其他用户的分类，也不直接查询默认分类模板作为结果。
2. 默认不返回已归档分类。
3. 支出分类按一级、二级分类组成树形结构；收入只返回一级分类。
4. 一级分类在相同金额类型内按照 `sort_order, id` 排序；二级分类在相同父分类下按照 `sort_order, id` 排序。
5. 返回结果可通过 `source_template_id != NULL` 派生 `isDefault`，用于前端区分默认来源分类和用户自定义分类；不需要向前端暴露模板的完整内容。

#### 创建分类

`CreateCategoryDto`：

| 字段       | 是否必填 | 说明                                                       |
| ---------- | -------- | ---------------------------------------------------------- |
| `type`     | 是       | `expense` 或 `income`                                      |
| `name`     | 是       | 分类名称                                                   |
| `iconKey`  | 是       | 图标资源标识，不允许为NULL                                 |
| `parentId` | 否       | 父级分类id；不传或为NULL时创建一级分类，传值时创建二级分类 |

业务要求：

1. 客户端不传 `level`，由后端根据 `parentId` 推导：`parentId` 为空时为一级分类，不为空时为二级分类。
2. 收入只允许创建一级分类，`type = income` 时不允许传入 `parentId`。
3. 创建二级分类时，父分类必须存在、未归档、属于一级分类，并且父子分类的 `type` 必须相同。
4. 创建二级分类时，父分类必须属于当前用户；父分类可以是默认来源分类，也可以是用户自定义分类。
5. 创建的自定义分类必须设置 `owner_user_id = userId` 和 `source_template_id = NULL`，不接受客户端指定所属用户或模板来源。
6. 创建前需要校验同一归属、金额类型和父分类下是否存在同名的未归档分类。
7. 新分类的 `sort_order` 取同一排序范围内当前最大值加1；范围内没有分类时从0开始。
8. 对外只保留一个 `create` 方法；Service内部可以根据 `parentId` 分别调用一级分类和二级分类的校验逻辑。

#### 编辑分类

`UpdateCategoryDto`：

| 字段      | 是否必填 | 说明                               |
| --------- | -------- | ---------------------------------- |
| `name`    | 否       | 新分类名称                         |
| `iconKey` | 否       | 新图标资源标识；传入时不允许为NULL         |

业务要求：

1. 只允许编辑当前用户自己的未归档分类；默认来源分类和用户自定义分类都允许编辑，其他用户的分类不可编辑。
2. 普通编辑只允许修改 `name` 和 `icon_key`，不允许修改 `owner_user_id`、`source_template_id`、`type`、`level` 和 `parent_id`。
3. 修改名称时，需要重新校验同一归属、金额类型和父分类下是否存在同名的未归档分类。
4. 修改图标时，`iconKey` 必须有值，不允许传入NULL；不修改图标时省略该字段。
5. 名称和图标通过同一个 `update` 方法进行局部更新，不拆分成“编辑名称”和“编辑图标”两个方法。
6. 如果未来支持将二级分类移动到其他一级分类，应单独设计移动分类的业务方法，不并入普通编辑。

#### 分类排序

`ReorderCategoriesDto`：

| 字段          | 是否必填 | 说明                                                       |
| ------------- | -------- | ---------------------------------------------------------- |
| `type`        | 是       | `expense` 或 `income`                                      |
| `parentId`    | 否       | 不传或为NULL时调整一级分类；传值时调整该父分类下的二级分类 |
| `categoryIds` | 是       | 当前排序范围内全部可见分类id组成的有序数组                 |

业务要求：

1. 调整一级分类时，所有分类必须属于同一个金额类型；调整二级分类时，所有分类必须属于同一个父分类。
2. `categoryIds` 必须覆盖当前排序范围内的全部可见分类，不能缺少、重复或者包含范围外的分类。
3. `categoryIds` 中的分类必须全部属于当前用户；默认来源分类和用户自定义分类都可以参与排序。
4. 在事务中按照 `categoryIds` 的数组顺序直接批量更新 `user_category.sort_order`，建议从0开始连续赋值。

#### 删除分类

1. 删除接口统一执行逻辑归档，设置 `archived_time`，不物理删除分类记录。
2. 只允许归档当前用户自己的未归档分类；默认来源分类和用户自定义分类都允许归档，其他用户的分类不可归档。
3. 归档一级分类前必须检查其下是否存在未归档的二级分类；如果存在则拒绝归档，用户需要先归档全部二级分类。
4. 已被金额记录引用的分类仍可归档，历史金额记录继续保留并能够读取该分类；创建或修改金额记录时不能再选择已归档分类。

#### 重置分类

重置属于批量覆盖操作，必须在数据库事务中完成：

1. 归档当前用户所有 `source_template_id = NULL` 的用户自定义分类。为满足父子约束，先处理二级分类，再处理一级分类。即使分类已被金额记录引用也只归档，不物理删除，历史关联继续保留。
2. 读取所有默认分类模板，按照 `owner_user_id + source_template_id` 查找当前用户对应的默认来源分类。
3. 已存在的默认来源分类使用原有分类id进行更新，将 `type`、`name`、`level`、`icon_key`、`sort_order` 和 `archived_time` 恢复为模板值，其中 `sort_order = default_sort`、`archived_time = NULL`。保留原id可以避免破坏历史金额记录关联。
4. 当前用户缺失的默认来源分类需要重新创建；先恢复或创建一级分类，再根据模板父子关系恢复或创建二级分类，并将 `parent_id` 指向当前用户的父分类记录。
5. 重置过程中应先归档用户自定义分类，再恢复默认来源分类，避免未归档分类名称冲突。
6. 重置完成后，用户可见分类应与全部默认分类模板一致，顺序恢复为模板的 `default_sort`；历史金额记录仍可读取其原来关联的已归档自定义分类。
