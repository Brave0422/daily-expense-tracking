## 1. 按阶段生成

每次任务先阅读主 PRD、公共文档和当前模块，完成一个可检查的阶段。不能把某个页面的模拟展示视为模块已完成，也不能为了同时做完所有页面跳过认证、契约和注释。

| 阶段 | 阅读 | 产物与完成条件 |
| --- | --- | --- |
| 1 工程与基础设施 | 01、02、08、09 | Flutter 工程、版本与依赖、主题、路由骨架、配置、模型、Dio 与安全 Cookie 存储；已有需求文档保留 |
| 2 账户与认证 | 03，复读公共文档 | 登录 / 注册 / 密码页面、会话恢复、共享刷新、退出；真实 API 和认证边界测试通过 |
| 3 分类与标签配置 | 05、06 | 两个配置模块及 SVG 适配；管理模式写接口、层级 / 重名 / 删除约束正确 |
| 4 流水 | 04、05、06 | 日明细、年内月汇总、筛选、创建 / 编辑 / 删除、标签草稿；真实后端业务闭环 |
| 5 统计 | 07 | 三个独立板块、触摸图表、精确文案与特殊状态 |
| 6 联调与交付 | 全部 | 跨模块刷新、会话隔离、异常路径、注释检查、Android 构建与可执行的平台验证 |

后续阶段不可以绕过前一阶段未解决的契约问题。无须每一步都重新询问已经确定的联网和 Cookie 方案；发现具体能力缺口时先写明差异。

## 2. 测试策略

以行为和重要边界为测试目标，不只检查实现中的某个变量值，也不为纯样式改动堆砌重复测试。

| 层级 | 重点 |
| --- | --- |
| 单元 / 契约测试 | 精确金额、自然日期、查询数组、空字段、省略写入 data、模型 nullable、验证码用途 |
| 网络与会话测试 | Cookie 保存 / 轮换、Storage 故障、并发 401、迟到旧 Token、网络故障与真正 401 区分、退出竞态 |
| Notifier / Repository 测试 | 表单提交锁、保存与刷新分别成功 / 失败、旧查询拦截、账号切换、数据失效关联 |
| Widget 测试 | 登录重定向、空 / 错误状态、筛选切换、归档关联、表单保留与放弃确认、基本语义 |
| 集成测试 | 真实开发服务上的登录 → 配置 → 记账 → 编辑 → 统计 → 删除 → 退出流程 |

网络 / 存储单元测试可以使用替身模拟错误和竞态；至少一次集成验收使用真实后端与独立测试账号。不能靠只会返回成功的 mock 证明网络与认证已完成。

## 3. 关键验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A-01 | 无 Cookie 首次启动 | 未登录，不闪业务页 |
| A-02 | 有有效 Cookie 重启 | 安全装载后刷新成功，进入业务页 |
| A-03 | 多个请求同时 401、以及旧请求迟到 | 共享刷新；旧 Token 不触发额外轮换；原请求最多重放一次 |
| A-04 | 恢复 / 刷新遇到超时或 5xx | 可重试，凭证不被误清理 |
| A-05 | 真正失效、退出或换账号期间有迟到请求 | 旧请求不能复活身份或污染数据 / Cookie |
| A-06 | 注册成功但自动登录失败 | 提示已注册并引导登录，不重复注册 |
| A-07 | 验证码前导零、冷却与前后台切换 | 字符串不丢零，截止时间生效，用途与邮箱正确 |
| T-01 | 日明细与月汇总切换、筛选无结果 | 请求参数合法，totals 与 filterTotals 语义保持正确 |
| T-02 | 0、负数、多于两位小数、超长金额 | 按创建 / 筛选不同规则校验，业务计算精确 |
| T-03 | 闰日、跨月 / 年、编辑发生日期 | 提交自然日期不跨天，修改后重查正确周期 |
| T-04 | 清空标题、备注、全部标签 | 编辑完整提交 null / []，不漏必填字段 |
| T-05 | 写入成功但查询失败；写请求超时 | 区分成功与结果不确定，不自动重复创建 |
| T-06 | 历史分类 / 标签已归档 | 原关联可显示并按规则保留，不能新绑定其他归档项 |
| C-01 | 收入建子分类、一级支出绑定流水 | 客户端禁止无效操作，后端错误可理解 |
| C-02 | 一级分类还有有效子分类时删除 | 提示先删除二级，不自动级联 |
| G-01 | 新标签同名、取消复用、重复绑定 | 明确确认，保留 ID，取消无副作用 |
| G-02 | 流水草稿新增 / 改名后取消；标签搜索旧响应迟到 | 不提前写标签，旧响应不覆盖当前结果 |
| G-03 | 删除流水关联独占 / 共享标签 | 以后端重查结果为准，标签与筛选选项更新 |
| S-01 | 独立板块、收入层级、多余查询字段 | 板块独立；收入一级；不发送无效字段 |
| S-02 | 归档分类与历史流水总额不同 | 采用统计口径，不用列表本地重算 |
| S-03 | 上期零、两期零、比例舍入零、完整周期零点 | new / unchanged / 方向正确，不画假饼图 |
| U-01 | 窄屏、键盘、文本放大、浅深色和系统返回 | 可读可操作，没有遮挡、溢出或草稿误丢 |
| Q-01 | 所有阶段代码与测试 | 变量、参数、方法和关键节点都有准确注释 |

文本长度用中文、英文和 emoji 检查客户端与服务端一致性；日期与统计边界按 API 文档补充测试。

## 4. 检查命令与平台说明

在 Flutter 工程创建后，根据实际目录运行：

```powershell
flutter pub get
dart run build_runner build --delete-conflicting-outputs
dart format --output=none --set-exit-if-changed lib test integration_test
flutter analyze
flutter test
flutter build apk --debug
```

上述目录尚未存在的早期阶段，只检查当前已有代码目录，不用空目录或忽略错误来伪造完成。代码生成前查看已有修改；生成器只更新对应产物，不删除需求文档。

集成测试示例：

```powershell
flutter test integration_test --dart-define=API_BASE_URL=<可访问的开发服务地址>
```

执行前确认设备、测试账户与开发后端配置。Android 在当前 Windows 环境完成运行 / 构建验证；iOS 需要 macOS / Xcode 和真实平台配置，条件不具备时明确列为未验证。

## 6. 阶段交付报告

交付时列出：本阶段实现的需求编号、修改文件、API 接入情况、实际检查结果、注释检查结果、平台验证范围和尚未解决的问题。

没有执行过的测试 / 构建不能写“通过”；未完成的范围不能用占位页替代后宣称完成。仅文档阶段不执行 Flutter 初始化或业务测试。

> 按 `app/PRD.md` 的阶段 4 实现流水模块。先确认账户认证已可联调，再阅读 04、05、06 与公共规范。复用已有配置能力，完成真实接口的查询、筛选、录入、编辑和删除，验证草稿取消、归档历史及写入后刷新。不要新增后端接口；变量、方法和关键节点必须写注释。
