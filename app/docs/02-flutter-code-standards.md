# 02 Flutter 代码与注释规范

[返回主 PRD](../PRD.md) · [项目基础](01-project-foundation.md) · [交付验收](10-delivery-and-acceptance.md)

## 1. 规范级别

本文件是所有生成阶段的强制要求，覆盖业务、基础设施、组件、测试和工具脚本。采用 Flutter 推荐的工程组织、Dart 空安全、Effective Dart 命名与格式化规则，并增加项目自己的中文注释要求。

**所有变量、所有方法均必须有注释；所有关键流程节点必须有注释。** 私有变量、局部变量、简单方法、生命周期覆盖方法和测试代码同样适用。不能用“命名已足够清晰”“只有一行代码”或“AI 生成代码”为理由跳过。

## 2. 命名与文件组织

- Dart 源文件与目录使用 `lowercase_with_underscores`，例如 `transaction_repository.dart`。
- 类型使用 `UpperCamelCase`，例如 `TransactionRepository`；变量、参数、方法和常量使用 `lowerCamelCase`。
- 私有成员使用 `_` 前缀；局部变量不使用私有前缀，也不采用类型前缀命名。
- 明确命名金额单位、日期含义和状态，例如 `amountInCents`、`occurredDate`、`isSubmitting`，不使用难以理解的缩写。
- 一个文件围绕一项主要职责；大页面按业务区域拆成 Widget，不将网络、校验、图表与整个页面全部写进一个文件。
- import 按 Dart SDK、第三方包、项目引用分组，组内保持一致顺序；跨业务模块使用清晰的公开接口。
- 自动生成的 `.freezed.dart`、`.g.dart` 由生成器维护，模型源文件必须完整记录字段与方法含义，不通过手改生成产物维护注释。

## 3. 变量与参数注释：必须逐项覆盖

| 对象 | 注释要求 |
| --- | --- |
| 顶层变量、常量、Provider、类字段、Widget 属性 | 声明前使用 `///`，说明用途及必要单位、取值、生命周期 |
| 模型属性、枚举类型与每个枚举值 | 使用 `///` 说明业务含义、空值及接口映射 |
| 方法参数、构造参数 | 在所属方法 / 构造器的文档注释中逐个使用 `[参数名]` 说明含义与约束 |
| 局部 `final`、`var`、循环变量、解构变量 | 紧邻声明使用 `//`，说明具体用途；多项解构应逐项解释 |
| 回调参数、错误与堆栈变量 | 回调前或入口处解释每个参数的职责；未使用参数说明忽略原因 |
| 测试与脚本变量 | 同样说明数据、替身、断言目标或执行用途 |

注释不能只重复名字。例如 `// 金额` 不够，应写明“本次输入的人民币元字符串，提交前校验正数及两位小数”。相邻多变量不能只写一句泛泛的“初始化数据”代替逐项说明。

## 4. 方法注释：必须逐项覆盖

每个函数、方法、构造器、getter、setter、局部函数和生命周期方法都需要注释。具名声明使用 `///`；匿名回调在声明前或回调入口提供对应说明。

方法文档应包含：

1. 做什么、在何时调用。
2. 各参数的含义及输入约束。
3. 返回结果的含义；无返回值也应说明完成后的行为。
4. 重要副作用，例如修改会话、更新状态、写入安全存储或触发刷新。
5. 可能的失败和处理策略；异步方法注明取消、并发或重复调用约束。

`build`、`initState`、`dispose`、`createState` 和 `@override` 方法不能因为来自框架而省略注释。中文注释为默认语言，标准类型名和接口字段保留英文。

## 5. 关键节点注释

下列步骤必须在代码对应位置写注释，说明“为什么这样处理”，必要时解释先后顺序：

- 启动初始化、安全存储读取、Cookie 装载与路由会话恢复。
- Authorization 注入、401 判定、共享刷新任务、Token 轮换、一次重放与防止刷新递归。
- 暂时网络故障与真正会话失效的区分；退出或账号切换后的请求取消与旧响应拦截。
- 表单校验、金额的字符串 / 整数分转换、自然日期的序列化。
- 标签同名复用、`tagNames` / `tagUpdates` 草稿的写入时机，以及归档关联的保留 / 移除规则。
- 写入成功但后续刷新失败、网络超时导致结果不确定，以及不自动重试写请求的原因。
- 请求序号、取消、生命周期判断、资源和订阅释放。
- 图表数值转换与原始金额文案分离、比例特殊值和完整周期轴处理。

普通代码不必逐行翻译语法，但不能省略上述节点或变量 / 方法的注释。

## 6. 注释示例

下面展示变量、参数、方法和关键节点的覆盖方式。业务校验的完整规则仍以模块文档为准。

```dart
/// 将符合接口格式的非负人民币元字符串转换为整数分。
///
/// [amount] 最多包含 13 位整数和 2 位小数，不包含货币符号。
/// 返回精确的整数分；格式错误时抛出 FormatException。
/// 本方法不修改页面状态，也不使用浮点数进行金额计算。
int parseYuanToCents(String amount) {
  // 校验接口接受的金额格式，拒绝负数、指数及超过两位的小数。
  final amountPattern = RegExp(r'^(?:0|[1-9]\d{0,12})(?:\.\d{1,2})?$');

  // 保存匹配结果，同时检查完整匹配，避免结尾换行被正则结束锚点放过。
  final amountMatch = amountPattern.firstMatch(amount);

  // 在转换之前拒绝非法输入，避免解析结果与后端金额规则不一致。
  if (amountMatch == null || amountMatch.group(0) != amount) {
    throw const FormatException('金额格式不正确');
  }

  // 元和小数部分分开处理，整个转换过程保持整数精度。
  final parts = amount.split('.');

  // 将整数元转换成分，输入上限在原生 Dart int 的可表示范围内。
  final wholeCents = int.parse(parts.first) * 100;

  // 不足两位的小数在右侧补零，无小数输入按零分处理。
  final fractionText = parts.length == 2 ? parts[1] : '0';

  // 精确的小数分，与整数元对应的分相加后构成完整金额。
  final fractionalCents = int.parse(fractionText.padRight(2, '0'));

  return wholeCents + fractionalCents;
}
```

注释随代码修改同步维护，不记录虚构作者、伪造测试结果或与实现不符的行为。

## 7. Dart 与 Flutter 实现规范

- 开启空安全；能用 `final` / `const` 时优先使用，控制可变状态的边界。
- 接口数据先经过类型化解析，不在页面传播 `dynamic`。可空字段、缺失 `data` 和未知错误均显式处理。
- 不用强制 `!` 掩盖空值；需要使用时注明已建立的前置条件。
- 金额业务计算不使用 `double`；日期不经 UTC 转换后再截取字符串。
- 控制流使用花括号；通过 `dart format` 统一格式，不手动对齐大量空格。
- 不在 `build` 中创建长期请求、Controller 或 Timer；通过生命周期和 Provider 管理依赖。
- 正确释放 Controller、FocusNode、Timer、监听器和订阅；异步返回后先确认对象 / 会话仍有效。
- 使用 Widget 的语义、主题和布局约束，不写大量固定位置，不用无边界列表嵌套造成布局错误。
- Repository 和 Service 不依赖 BuildContext；提示和导航由 UI / 应用协调层执行。
- 不吞掉异常，不输出密码、验证码、Token、Cookie 或包含敏感字段的完整请求日志。

## 8. 静态检查与注释验收

- `analysis_options.yaml` 引入 `package:flutter_lints/flutter.yaml`，启用适合当前 SDK 的严格类型检查。
- 不通过整文件忽略规则绕过静态错误；必要的局部忽略要写明原因。
- `dart format --output=none --set-exit-if-changed lib test integration_test`、`flutter analyze` 和相应测试通过后才能交付阶段成果。
- Analyzer 不会自动检查所有私有 / 局部变量的中文注释。交付时必须逐文件检查：变量、参数、方法、关键节点是否覆盖，以及注释是否准确。
- 检查包括测试文件和新增脚本；代码生成的源声明同样检查。缺少注释就是未完成，不能作为可选优化推迟。

官方参考：[Effective Dart 命名与格式](https://dart.dev/effective-dart/style)、[Dart 文档注释](https://dart.dev/effective-dart/documentation)。本项目的“所有变量、所有方法、关键节点均注释”要求更具体，实施时必须同时满足。
