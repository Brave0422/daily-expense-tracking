# 08 页面与移动交互

[返回主 PRD](../PRD.md) · [项目基础](01-project-foundation.md) · [代码规范](02-flutter-code-standards.md)

## 1. 导航结构（UI-01）

使用三个底部主导航：“流水”“统计”“我的”。流水为默认入口，并提供清晰的“记一笔”按钮；记录表单、配置编辑和密码页面作为独立二级页面 / 面板。

| 页面 | App 内路由建议 | 登录要求 |
| --- | --- | --- |
| 启动 / 会话恢复 | `/bootstrap` | 恢复前统一入口 |
| 登录 | `/login` | 访客 |
| 注册 | `/register` | 访客 |
| 忘记密码 | `/forgot-password` | 访客 |
| 流水 | `/transactions` | 已登录 |
| 新增流水 | `/transactions/create` | 已登录 |
| 编辑流水 | `/transactions/:id/edit` | 已登录，必须有当前记录数据 |
| 统计 | `/statistics` | 已登录 |
| 我的 | `/account` | 已登录 |
| 分类管理 | `/account/categories` | 已登录 |
| 标签管理 | `/account/tags` | 已登录 |
| 修改密码 | `/account/change-password` | 已登录 |

这些是客户端路由，不是后端 API。使用 go_router 管理主导航分支，切换分支保留当前会话的筛选和滚动位置；退出后全部清理。

恢复未完成时停留启动页；未登录不进入业务页面；已登录访问访客页返回默认业务入口。会话失效回登录并移除旧页面栈，不通过返回按钮进入旧账号页面。

编辑页通过当前列表记录回填。路由恢复后缺少记录时回到列表重查，不支持凭 ID 直接从不存在的详情接口加载。首版不承诺外部深链接、推送入口或恢复未提交表单。

## 2. 页面布局（UI-02）

- Material 3 为主体；适配安全区域、状态栏、底部手势区域和键盘，不复制 PC 固定侧栏或宽表格。
- 流水：年月 / 模式、总览卡、筛选、分组列表、记一笔；单条操作使用明确菜单或编辑入口。
- 统计：排行 / 占比 / 趋势子标签，各板块拥有自己的筛选，条件过多时换行或使用筛选面板。
- 我的：会话状态、分类管理、标签管理、修改密码、退出；恢复后没有邮箱数据时仅显示已登录。
- 列表使用懒加载组件；标题、分类名和备注长度变化时合理截断 / 展开，关键金额不能被截成无法判断的数值。
- 界面以手机竖屏为主，同时检查窄屏、键盘弹出与横屏下的滚动和布局约束。

## 3. 视觉与资源（UI-03）

- 主题集中管理，主色参考现有 [Web Design Token](../../web/src/styles/tokens.css)，不在页面散落固定颜色。
- 初版支持跟随系统浅色 / 深色主题；不必增加主题设置接口。
- 收入、支出使用明确文字 / 符号和可区分颜色；错误、危险操作、正常提示遵循统一语义。
- 金额统一显示货币含义和两位小数；提交值不包含 UI 的 ¥、千分位或正负展示符号。
- 分类 iconKey 与 SVG 的映射集中维护，保留原资源来源与许可说明，不以图标名称猜测任意图片 URL。
- 现有 SVG 使用 CSS 背景变量。App 资源适配时分离背景与中心图案，由 Widget 绘制后端颜色的圆形背景，用 flutter_svg 显示图案。
- 未知图标或资源失败显示通用占位，不影响记录、分类选择或金额展示。
- 图表扇区颜色与分类图标颜色分开处理，图表交互遵循统计模块要求。

## 4. 表单与返回（UI-04）

- 标签、金额、邮箱、密码和日期使用适合的输入键盘；密码支持显示切换，关闭页面清理敏感输入。
- 小数键盘不是唯一校验来源；粘贴、不支持的小数位、货币符号和非法日期仍需验证。
- 错误放在对应字段附近；提交时聚焦首个错误，保留其他已填内容。
- 长表单可滚动，键盘不遮挡正在输入的字段和保存操作；底部固定按钮需处理安全区和键盘。
- 编辑 / 新增有未保存改动时，系统返回、顶部返回和支持的返回手势都经过放弃确认。
- 正在提交时防止重复保存和意外关闭；结果回来后关闭已失效页面前检查生命周期。
- 一次点击只触发一次动作，删除菜单不得同时触发行编辑。
- 支出一级 / 二级选择、图标选择和标签复用弹窗有明确取消路径，取消只撤销草稿。

## 5. 统一页面状态（UI-05）

| 状态 | 要求 |
| --- | --- |
| 首次加载 | 展示占位或进度，避免先闪空状态 |
| 正常结果 | 显示当前查询上下文与真实数据 |
| 无记录 | 说明当前周期无数据，并提供相关创建入口 |
| 筛选无匹配 | 说明筛选无结果，提供重置筛选 |
| 首次请求失败 | 明确错误与重试，不伪装为零金额 |
| 刷新失败 | 可保留已加载内容，标识未刷新成功 |
| 写入失败 | 保留输入，显示可理解的错误 |
| 写入结果不确定 | 提醒查询确认，不自动重放写请求 |
| 会话失效 | 统一清理并转登录，提示重新登录 |

Snackbar 用于轻量成功反馈；重要失败在当前页面可持续看到；删除与放弃草稿使用确认对话框。不能仅显示短暂提示后把关键错误隐藏。

## 6. 无障碍与平台行为（UI-06）

- 点击目标默认至少 48 逻辑像素，图标按钮有语义标签，统计信息有文字替代。
- 不只靠颜色区分方向、选中或错误；保证浅色 / 深色下文字可读。
- 检查系统字体缩放，金额、按钮和表单不得因放大而溢出；不全局锁死文本缩放。
- 触摸操作不依赖 hover；图表与图例通过点按 / 滑动操作。
- 使用当前 Flutter 支持的返回处理 API，验证 Android 系统返回与 iOS 返回手势。
- 页面关闭时释放输入控制器、焦点、Timer 和监听，异步响应不能弹出已离开的页面提示。

## 7. 验收

主导航状态保持正确；登录恢复没有页面闪跳；退出后的返回栈不泄露旧数据；表单返回确认、键盘避让和取消流程完整；中文长文本、浅深色、文本放大和触摸图表均可使用。
