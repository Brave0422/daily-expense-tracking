# 04 流水管理

[返回主 PRD](../PRD.md) · [API 契约](09-api-contracts.md) · [分类](05-categories.md) · [标签](06-tags.md)

## 1. 目标与入口

流水是登录后的默认页面。用户可以查看收支、筛选记录、记一笔、编辑和删除。移动端复用现有接口，不增加服务器分页、单笔详情或离线保存接口。

页面包括周期与模式选择、完整周期总览、筛选入口、结果区域和“记一笔”入口。日明细与月汇总是不同查询模式，不能将日明细数组在 App 中自行聚合成月汇总替代后端。

## 2. 日明细（TX-01）

- 默认查询当前自然月，按 `GET /api/transactions/daily` 返回的日期和记录顺序显示。
- 周期支持月份选择和前后切换，标题明确显示当前年月。
- 总览显示本月收入、支出和结余，直接使用 totals；筛选生效时另外展示 filterTotals，标明是筛选合计。
- 按日分组显示当日收入 / 支出；单笔展示类型、金额、分类、可选标题、标签和备注入口。
- 支出展示一级 / 二级分类；收入 secondary 为 null，不能出现空的二级分类占位。
- 已归档分类或标签标注“已删除”或“已归档”，历史记录仍可识别原关联。
- 点击单笔进入编辑页或编辑详情页；数据来自当前查询的记录，不调用不存在的 `GET /api/transactions/:id`。
- 下拉刷新重新查询当前条件。无分页接口，不显示“加载下一页”或向后端提交 page / pageSize；使用懒加载列表提高渲染效率。

## 3. 年内月汇总（TX-02）

- 切换到月汇总时按年份调用 `GET /api/transactions/monthly-summary`，默认当前年。
- 总览显示全年 totals 与筛选 filterTotals；结果按接口 months 顺序展示各月收支和分类汇总。
- 支出分类按一级 / 二级结构展示，收入按一级展示；金额使用接口结果，不重新求和。
- 月汇总不提供单笔编辑 / 删除；可设置“查看该月明细”操作，进入对应月份的日明细。
- 从汇总进入日明细只继承兼容的收支、分类和金额筛选，不携带不支持的字段。

## 4. 筛选（TX-03）

| 条件 | 日明细 | 月汇总 |
| --- | --- | --- |
| 收支类型 | 全部 / 支出 / 收入 | 同左 |
| 分类 | 多选，可选支出一级及二级 / 收入一级 | 同左 |
| 最小 / 最大金额 | 非负元字符串，可为零 | 同左 |
| 标签 | 多选，任一匹配 | 不支持，隐藏且不提交字段 |
| 标题、备注 | trim 后文本筛选 | 不支持，隐藏且不提交字段 |

- 使用全屏或可滚动底部筛选面板；“应用”校验后请求，“重置”恢复当前周期默认筛选。
- “全部”在请求中省略 type，不发送 all；未设置的字段省略。
- ID 数组重复键序列化；空金额、标题和备注不提交；最小金额不得大于最大金额。
- 历史筛选选项可查询 `includeArchived=true` 并标识归档状态，不能因配置删除导致历史条件无法选择。
- 每种模式保留自己的筛选草稿。切换模式时只构造该模式允许的参数，不能发送隐藏字段的空值。
- 修改收支类型时清理不属于该类型的已选分类；来源无效或已删除的筛选项显示状态，不偷偷映射为其他 ID。
- 快速切换月份、类型或筛选时取消旧查询并拦截旧响应。

## 5. 新增流水（TX-04）

默认支出、发生日期为本机当前自然日期，金额与分类为空；用户也可以录入其他有效日期，不按今天强制截断。

| 字段 | UI 与校验 |
| --- | --- |
| 类型 | 支出 / 收入；切换时清空不兼容分类 |
| 金额 | 小数键盘；大于零，最多 13 位整数和 2 位小数；不自动四舍五入错误输入 |
| 分类 | 必选；支出先选一级再选二级，收入选择一级 |
| 日期 | 必选自然日期；用年月日格式化为 YYYY-MM-DD |
| 标题 | 可选；trim 后最多 50 字符 |
| 标签 | 已有标签选择、新标签草稿、已有标签改名草稿 |
| 备注 | 可选；trim 后最多 100 字符，可多行 |

- 类别选项来自服务端；支出一级不能直接作为流水的 categoryId。
- 标签具体规则见标签文档；未保存流水前不写入新标签或标签改名。
- 保存前完整校验；提交按钮进入加载态，防止重复请求。
- 服务端成功后才提示“保存成功”，关闭表单并使流水、统计和相关标签查询失效。
- 写入成功但重查失败时提示“已保存，列表刷新失败”，提供刷新，不能再次执行创建。
- 请求超时时提示“结果尚未确认，请刷新列表确认后再重试”，不静默重复创建。
- 分类为空或加载失败时提供重试 / 分类管理入口，不替用户创建默认分类。

## 6. 编辑流水（TX-05）

- 回填当前记录，保持独立草稿；取消不改变原列表中的记录。
- 类型固定不可编辑，PATCH 请求不包含 type。
- 完整提交 categoryId、amount、occurredDate、title、tagIds、remark；空标题 / 备注为 null，清空标签为 []。
- 原有归档分类可以继续保留，原有归档标签可以保留或移除；标识历史状态，不允许把其他归档项作为新关联。
- 更换分类只选未归档且层级、类型匹配的分类；归档原分类被替换后不作为新的可选项。
- 归档标签不能改名；已有有效标签改名保持原 ID，随流水提交 tagUpdates，并提示会影响使用该标签的其他记录。
- 发生日期变更可能使记录离开当前月份；保存后重查原查询上下文，必要时提供查看新月份的操作。
- 进入编辑缺少记录数据时返回列表重查；不根据路由 ID 拼出模拟详情。重新查询发现记录已不可用时提示并关闭编辑。

## 7. 删除流水（TX-06）

- 通过明确的删除操作打开确认，不因普通点击列表行触发删除。
- 确认中说明目标记录与金额，并说明仅由这笔记录使用的标签也可能被删除，其他记录仍使用的标签保留。
- 确认后调用 `DELETE /api/transactions/:id/archive`，加载期间禁止重复确认；失败保留上下文并展示错误。
- 成功后重新查询流水、统计、标签列表及标签筛选选项，不在客户端推测哪些标签会被归档。
- 用户从流水草稿移除标签只表示解绑，不调用全局标签删除接口。

## 8. 页面状态与验收

1. 没有记录与筛选后无结果使用不同提示；空结果仍显示服务端返回的周期及总览。
2. 首次失败有重试；刷新失败可保留旧内容但明确状态，写入不使用离线队列。
3. 记录跨月、原分类 / 标签归档、所有标签清空、空收入二级分类均正确处理。
4. 日明细与月汇总不混用筛选或 totals / filterTotals，不发送未知分页参数。
5. 保存 / 删除只请求一次；已保存后重查失败不重复写入。
6. 标签草稿取消无副作用，金额精确、日期不跨天，旧响应不覆盖新周期。
