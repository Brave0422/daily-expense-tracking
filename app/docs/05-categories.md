# 05 分类管理

[返回主 PRD](../PRD.md) · [API 契约](09-api-contracts.md) · [流水管理](04-transactions.md)

## 1. 目标与入口

从“我的 → 分类管理”进入。提供收入 / 支出切换、分类树、创建、名称与图标修改及删除；本模块操作立即写入服务端，与流水的标签草稿模式不同。

## 2. 分类结构（CAT-01）

- 支出采用一级分类和二级分类，流水实际绑定二级分类。一级行可展开子分类，并提供添加二级入口。
- 收入只允许一级分类，不显示添加子分类操作。
- 按服务端顺序显示，不自行重排，不实现当前后端没有的拖拽排序、重置或归档恢复。
- 配置管理默认仅展示未归档项；历史关联与历史筛选由流水模块单独处理。
- 名称相同但父级不同的二级分类是不同 ID，不合并。

## 3. 创建（CAT-02）

创建一级支出 / 收入提交 type、name、iconKey；创建支出二级额外提交有效一级 parentId。父级与类型必须匹配，不能建立第三层。

- 名称 trim 后必填，最多 50 字符；同类型、同父级下未归档分类不能重名。
- 图标必选，来自 `GET /categories/getAllIcons`；不上传图片或随意编造 iconKey。
- 显示新分类预览；二级背景色遵循父级颜色，不提供用户颜色编辑。
- 成功后关闭编辑页 / 面板并重新请求当前类型分类树，按服务端新增排序显示。
- 失败保留输入与当前父级，展示后端错误；加载分类或图库失败时有重试。

## 4. 编辑（CAT-03）

- 只修改 name 和 iconKey；id 取原记录，type、level、parentId 为只读。
- 不通过编辑将收入变为支出、一级变为二级或移动到其他父级。
- 修改默认分类的展示名称 / 图标使用同一接口，不篡改服务端模板。
- 提交时调用当前的 `POST /categories/update`，不要凭 REST 命名习惯猜测 PATCH 路径。
- 成功后刷新分类树，并使流水选项 / 历史展示与统计数据失效。

## 5. 删除（CAT-04）

- UI 文案使用“删除”，实际调用归档端点，确认中说明历史流水保留关联信息。
- **一级分类存在未归档二级分类时，当前后端拒绝删除。** 必须提示先删除二级分类，不能实现客户端自动批量级联删除。
- 删除二级或无有效子分类的一级后，刷新配置、流水选项 / 历史展示与统计。
- 统计会排除归档分类关联金额，确认文案应让用户知道此操作会影响统计结果。
- 服务端拒绝或网络失败时保留当前上下文并显示错误；不先从 UI 永久移除记录假装成功。

旧文档或控制层注释中若提到联动删除，以当前 `CategoriesService.archive` 的实际约束为准。

## 6. 图标与空状态

- iconKey 映射到 App 的本地适配 SVG；颜色使用服务端返回 backgroundColor。
- 图库加载为空时阻止无效提交，提示重试；未知 iconKey 使用通用占位并记录不含敏感数据的诊断，不能导致页面崩溃。
- 类型下无分类时显示创建入口。支出只有一级、没有二级时，在记账选择器引导添加二级分类。
- 删除或编辑期间禁用对应表单的重复操作，取消不产生写请求。

## 7. 验收

- 收入无法创建二级，支出无法选择错误父级或直接将一级绑定流水。
- 同父级重名错误可修正；其他父级的同名二级正常区分。
- 编辑不改变类型 / 父级；没有排序、重置或恢复请求。
- 一级有有效子分类时明确阻止删除，不生成“联动删除成功”的假结果。
- 图标、继承背景色、归档历史与统计变化符合服务端返回结果。

所有变量、方法和创建 / 归档 / 刷新关键节点按 [代码规范](02-flutter-code-standards.md)提供注释。
