# 06 标签管理

[返回主 PRD](../PRD.md) · [API 契约](09-api-contracts.md) · [流水管理](04-transactions.md)

## 1. 两种使用场景

| 场景 | 保存时机 | 接口 |
| --- | --- | --- |
| 我的 → 标签管理 | 用户确认标签创建 / 改名 / 删除时立即保存 | 标签写接口 |
| 流水表单中的标签 | 当前仅变更草稿，确认保存流水时一起提交 | check-name 为只读；写入使用流水接口 |

同一组件可共享输入和校验，但必须显式区分模式，不能在流水草稿中误调用全局写接口。

## 2. 配置管理（TAG-01）

- 展示未归档标签，按接口顺序显示；提供添加、编辑、删除和关键词搜索。
- 名称 trim 后非空，最多 50 字符；当前用户未归档标签不能重名。
- 添加调用 POST /tags；编辑调用 PATCH /tags/:id，保持原 ID 与历史关联。
- 改名提示会影响使用该标签的记录，不能把改名当作给某一流水创建副本。
- 删除确认使用当前名称；调用归档端点，历史关联保留，配置列表不再用于新绑定。
- 删除标签不会删除已有流水，不得自动请求流水删除接口。
- 提交失败保留输入与上下文；成功后重新执行当前列表 / 搜索，并通知流水选项与历史展示刷新。

## 3. 搜索（TAG-02）

- 有非空关键词时调用 GET /tags/search?key=...；关键词 trim 后最多 50 字符。
- 输入去抖建议 300ms；取消旧请求，并用序号防止迟到响应覆盖新关键词。
- 关键词为空时调用 GET /tags，不发送空 key。
- 添加 / 编辑 / 删除后保留当前关键词重查；改名后不匹配关键词的项自然离开结果。
- 搜索失败与无匹配结果区分展示；不把后端搜索改成只过滤已加载的一小部分本地数据。

## 4. 流水中的已有标签与新草稿（TAG-03）

1. 选择已有有效标签，以 ID 去重，同一流水不重复绑定。
2. 输入新名称后先校验，再通过 GET /tags/check-name 查询同名有效标签。
3. 若返回 null，添加本地名称草稿，不调用 POST /tags，也不伪造服务端 ID。
4. 若已有同名标签，明确询问是否复用；只有确认后才加入该真实标签的 ID，取消不自动合并。
5. 若同名标签已在当前选择中，提示“当前流水已添加该标签”。
6. 草稿已有同名项时直接提示，不加入重复 tagNames。

保存流水时，已有标签发送 tagIds，新名称发送 tagNames；服务端完成事务后重查。查重结果可能因其他设备并发而变化，最终写入错误由服务端裁决，App 不静默改为另一个标签。

## 5. 流水中的改名草稿（TAG-04）

- 对已有有效标签改名保留原 ID，待保存流水时提交 `tagUpdates: [{id, name}]`，对应 id 必须仍在 tagIds 中。
- 用户确认改名时只更新本地草稿，不能先发送 PATCH /tags/:id。
- 新名称已属于其他有效标签时提示冲突，不把原标签替换为另一个 ID。
- 用户取消流水或移除该标签时，相应改名草稿一并取消，不产生数据库副作用。
- 有效标签改名会影响其他历史关联记录，必须显示明确说明。
- 未保存新标签改名仅修改其 tagNames 草稿，不发送 tagUpdates。

## 6. 归档与移除（TAG-05）

- 编辑流水时允许保留当前原有归档标签，标注状态；不得新增绑定其他归档标签。
- 归档标签不可改名，允许从当前流水移除。移除表示解绑，不能调用全局删除接口。
- 后端删除流水可能归档没有其他未删除流水引用的标签；该操作后重新加载标签及筛选选项。
- 多个历史记录共享标签时，保留服务端给出的关联与状态，不由客户端引用计数决定删除。

## 7. 验收

- 配置模式确认会写入；流水草稿模式确认不写入，取消流水不会留下新标签 / 改名。
- 同名复用经过明确确认；不使用名字替代 ID，不重复绑定。
- tagUpdates 与 tagIds 对应，归档标签只保留 / 移除，改名影响范围有提示。
- 快速搜索、清空搜索和搜索中增删改不被旧响应覆盖。
- 标签删除与流水删除互不混淆，独占标签后续状态以重查为准。

所有变量、方法，以及草稿 / 持久化边界、同名复用与旧响应拦截节点按 [代码规范](02-flutter-code-standards.md)提供注释。
